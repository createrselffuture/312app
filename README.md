# VPN312 для Android — исходный код

Приложение-клиент WireGuard для сервиса VPN312. Это исходник версии **1.4** (versionCode 5). Готовый APK лежит на https://vpn312.store/app/download.

## Что делает приложение

- Вход по логину и паролю сайта или по одноразовой ссылке из Telegram-бота. Ссылку `vpn312://login` может открыть любой сайт или приложение, поэтому перед входом по ней приложение всегда спрашивает подтверждение.
- Показывает список ваших устройств. Выбранное устройство подключается встроенным WireGuard (библиотека `com.wireguard.android:tunnel`), отдельное приложение WireGuard не нужно. Новое устройство по умолчанию называется моделью телефона — название можно поменять при создании.
- **Автосмена сервера** (включена по умолчанию, выключается на главном экране). Когда через текущий сервер пропадает интернет или падает скорость, приложение переносит **то же самое устройство** (тот же ключ) на другой сервер и само переподключается. Для переноса приложение отправляет серверу приватный ключ устройства: этот ключ создал сам сервер, когда создавал устройство, так что нового он ничего не узнаёт.
- Оплата: СБП (открывается страница оплаты) и криптовалюта (вы вводите TXID, сервер проверяет транзакцию). Автоплатежей нет.
- Конфиг можно передать на другое устройство: QR-код, файл `.conf` или буфер обмена (с пометкой «секретно»).
- Обновление без Google Play — см. ниже.

## Трафик во время смены сервера

Пока приложение ищет новый сервер, туннель **не выключается**: трафик телефона по-прежнему уходит в VPN. Свои запросы к API приложение в это время шлёт через сеть телефона (Wi‑Fi или мобильную) мимо своего VPN (`DirectNet.kt`). Android разрешает это только приложению, которое держит этот VPN, и только для его собственных соединений.

Когда новый сервер найден, Android пересоздаёт туннель. На эмуляторе с Android 14 телефон около 0,25 с оставался без VPN: соединение, открытое в это окно, идёт мимо VPN, пока не закроется. Закрыть это окно может только сам Android. В приложении откройте «Настройки → Постоянный VPN — настройки Android» и включите для VPN312 «Постоянная VPN» и «Блокировать соединения без VPN». На эмуляторе с этой блокировкой мимо VPN не ушло ни одного соединения, а приложение по-прежнему достаёт до API и меняет сервер.

Если сеть без VPN не нашлась, вместо туннеля ставится «заглушка» (`TunnelManager.blackhole`). Весь трафик телефона уходит в VPN и там отбрасывается, а само приложение исключено из заглушки и ходит к API напрямую. В этом случае туннель пересоздаётся дважды.

До версии 1.3 туннель на время смены выключался, и несколько секунд трафик телефона шёл мимо VPN.

## Куда ходит приложение

| Адрес | Зачем |
|---|---|
| `https://vpn312.store/api/app/v1/*` | вход, устройства, оплата, конфиг приложения, отчёты об ошибках; во время смены сервера — через сеть телефона мимо VPN |
| запасные адреса API из конфига сервера (только `https://`) | то же самое, если основной адрес недоступен; запрос идёт вместе с токеном сессии |
| `https://www.gstatic.com/generate_204`, `https://cp.cloudflare.com/generate_204` | проверка «есть ли интернет через VPN», раз в 15 секунд, через туннель |
| `https://speed.cloudflare.com/__down?bytes=1000000` | замер скорости (1 МБ) через туннель: раз в 20 минут на безлимитной сети, раз в час на мобильной |
| ссылка на APK из конфига сервера (только `https://`) | обновление приложения |
| серверы WireGuard из вашего конфига | сам VPN |

Запасные адреса API, адреса проверок и пороги автосмены приходят с сервера в конфиге приложения (`GET /config`). Без сети приложение берёт последний сохранённый конфиг.

## Обновление

- Приложение скачивает APK только по `https://` и сверяет sha256 с конфигом сервера. Без контрольной суммы обновление не ставится.
- Каждое обновление ставится только после **системного окна подтверждения** Android (`USER_ACTION_REQUIRED`). Тихой установки нет. До версии 1.3 после первого разрешения Android обновления ставились без системного окна.
- Android не установит обновление с другой подписью: выпустить его может только владелец ключа VPN312.
- Сервер может объявить версию устаревшей. Тогда приложение показывает только экран обновления.

## Что хранится на телефоне

Шифруются ключом из Android Keystore (`Storage.kt`):
- токен сессии;
- конфиг устройства (в нём приватный ключ WireGuard);
- кэш профиля: логин, ник в Telegram, список устройств. Токена и конфига в кэше нет: они вырезаются перед сохранением.

Открыто, в обычных настройках приложения:
- номер, название и регион выбранного устройства;
- переключатели;
- последний рабочий адрес API;
- конфиг приложения с сервера.

Файл `.conf`, отправленный «Файлом», лежит в кэше приложения, пока его забирает другое приложение. Через 10 минут он удаляется: при следующем открытии приложения или при старте его процесса.

Данные приложения не попадают в облачные резервные копии (`allowBackup="false"`). Другие приложения их прочитать не могут. Но при извлечении данных с телефона (root, криминалистика) открытая часть будет видна.

## Отчёты об ошибках

Журнал пишется в память приложения: два файла по 400 КБ, старые записи перезаписываются по кругу. Ключи WireGuard, токены и пароли вычищаются ещё до записи (`AppLog.redact`).

- **Вы отправляете сами:** «Настройки → Журнал ошибок».
- **Отправляется само:** если приложение упало, отчёт уходит при следующем запуске. Выключается переключателем «Отправлять отчёт о сбое автоматически» в «Настройки → Журнал ошибок»; сервер тоже может выключить это флагом `features.crash_reports`.

В отчёте:
- версия приложения;
- версия Android и модель телефона;
- состояние VPN, номер устройства и регион;
- журнал приложения и logcat **только своего процесса** — чужие приложения туда не попадают.

Смотрите `AppLog.buildReport`.

## Сборка

Нужны JDK 17 и Android SDK (platform 34).

```bash
echo "sdk.dir=/путь/к/android-sdk" > local.properties
sh gradlew assembleRelease -Pvc=5 -Pvn=1.4
```

Без ключа подписи получится `app/build/outputs/apk/release/app-release-unsigned.apk`. Его можно подписать своим ключом (`apksigner sign`) и поставить. Обновления из приложения на такую сборку не встанут: у них другая подпись.

## Как проверить готовый APK

- sha256 файла `VPN312-1.4.apk`: `5250de5271e1be4a7201c3ff5a017bd6312d7d1a1cce7a60a6f099bdc5905f06`
- Сертификат подписи: `CN=VPN312, O=VPN312`, SHA-256 `7fb12bfb0dea144d193e4e206589d782699a5aff61831ff51d9876eefab05a58`
  (проверка: `apksigner verify --print-certs VPN312-1.4.apk`)

Пересборка этого исходника (`sh gradlew assembleRelease -Pvc=5 -Pvn=1.4`, JDK 17, build-tools 34) даёт те же файлы, что лежат внутри выложенного `VPN312-1.4.apk`. При нашей проверке sha256 совпали у всех 85 файлов, в том числе `classes.dex`, `AndroidManifest.xml`, `resources.arsc` и нативных библиотек WireGuard, — и при сборке из клона этого репозитория тоже: запись хеша коммита git в APK отключена (`vcsInfo`). Отличается только подпись.

Профиль ускорения запуска (`assets/dexopt/baseline.prof*`) иногда выходит разным от сборки к сборке. На другой версии JDK или SDK результат может отличаться.

В блоке подписи APK только сама подпись v2. Блок `DEPENDENCY_INFO` (список библиотек, зашифрованный ключом Google Play), который сборка Android добавляет по умолчанию, отключён настройкой `dependenciesInfo` в `app/build.gradle.kts`.
